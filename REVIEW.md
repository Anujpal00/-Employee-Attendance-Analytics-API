# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Used `punch_in.replace(hour=h, minute=m)`. For overnight shifts (e.g., shift starting 22:00 yesterday) or shifts crossing midnight, this pinned the shift start to punch-in's calendar day, producing wrong or negative elapsed times. | Overnight employee punching in at 01:30 IST for a 22:00 shift got assigned shift start 22:00 same day (producing a negative offset and 0 late minutes instead of 210). | Made the function take attendance date explicitly and resolve the correct shift start datetime in IST. |
| 2 | `compute_late_minutes` (line 37) | Checked `minutes > 10` where `minutes = int(total_seconds / 60)`. Because integer division truncates towards zero, a punch-in at 10 min 01 sec (601 seconds) evaluated to 10 minutes, failing `10 > 10` and incorrectly returning 0. | Punching in at 09:40:01 for a 09:30 shift returned 0 instead of 10 minutes late (violating rule R2). | Checked elapsed seconds strictly: `diff_sec > 600`, then computed `int(diff_sec // 60)` to floor minutes since shift start. |
| 3 | `compute_work_hours` (line 41) | Used Python's built-in `round(seconds / 3600, 2)`, which performs banker's rounding (round-half-to-even) instead of rule R4's required half-up rounding. | Work duration of 16362 seconds (4.545 hours) rounds to 4.54 with banker's rounding instead of 4.55. | Replaced with `Decimal(seconds) / Decimal(3600)` quantized with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` (lines 44–47) | Did not enforce rule R3's 30-minute minimum threshold; returned any positive minutes. Also placed `shift_end` on the same calendar day even for overnight shifts. | 15 minutes past shift end returned 15 instead of 0. For a 22:00–06:00 overnight shift, `shift_end` was computed as 06:00 on the shift start date instead of the next day. | Handled next-day shift end for overnight shifts (`shift_end <= shift_start`) and returned overtime only if minutes >= 30, else 0. |
| 5 | `/health` (lines 72–74) | Did not test database connectivity; returned static `{"status": "ok"}` even when MongoDB was unreachable. | Stopping the MongoDB instance still resulted in `/health` returning 200 OK instead of 503 Service Unavailable. | Added `client.admin.command("ping")` inside a try/except block; raises HTTPException 503 on failure. |
| 6 | `create_employee` (line 79) | Checked uniqueness with `find_one()` before `insert_one()` (check-then-insert pattern). Susceptible to race conditions under concurrent requests. | Sending two concurrent POST requests with the same `emp_code` created duplicate documents or race errors. | Created a unique index on `emp_code` at startup and caught PyMongo `DuplicateKeyError` to return 409 Conflict. |
| 7 | `create_employee` (line 82) | Assigned `datetime.now()` (naive local server time) to `created_at`. In responses, returned raw datetime instead of epoch milliseconds. | Client response received ISO string or naive datetime instead of an integer epoch milliseconds value. | Used `datetime.now(timezone.utc)` and converted `created_at` to integer epoch milliseconds in the API response. |
| 8 | `EmployeeIn` (lines 53–60) | Lacked schema validation for `emp_code` pattern (`^EMP\d{4,6}$`), email format, field length constraints, and rule that `shift_start` must differ from `shift_end`. | POST `/employees` accepted invalid employee codes like `"XYZ"` and identical shift times `"09:30"` / `"09:30"`. | Added regex patterns, string length limits, and a Pydantic model validator verifying `shift_start != shift_end`. |
| 9 | `list_employees` (line 93) | Calculated skip as `page * page_size`. For page 1, this skipped the first 20 records and returned the second page. | Calling `GET /employees?page=1&page_size=20` returned 0 items on a database with 6 employees. | Corrected pagination formula to `(page - 1) * page_size`. |
| 10 | `list_employees` (line 94) | Calculated `total` using `db.employees.count_documents({})`, ignoring the active `department` filter. | Filtering by `department=Sales` returned 2 records but reported `total: 6`. | Passed the query filter `q` into `count_documents(q)`. |
| 11 | `list_employees` (line 95) | Did not sort results; returned documents in arbitrary storage order. | Records were not sorted by `emp_code` ascending as required by the contract. | Added `.sort("emp_code", 1)` to the cursor. |
| 12 | `punch_in` (line 101) | Assumed employee existed (`emp = db.employees.find_one(...)`) without checking for `None`. | POST `/attendance/punch-in` with non-existent `emp_code` crashed with `TypeError: 'NoneType' object is not subscriptable` (HTTP 500). | Checked if `emp` is None and raised HTTP 404 Not Found. |
| 13 | `punch_in` (line 102) | Used `datetime.fromtimestamp(body.punched_at / 1000)` which creates a naive datetime in local system timezone, and did not truncate milliseconds to whole seconds. | Punching in with milliseconds (e.g. 09:30:00.750) stored sub-second precision, violating rule R1. | Truncated epoch ms using `(ms // 1000) * 1000` and created timezone-aware UTC datetime. |
| 14 | `punch_in` (line 103) | Extracted calendar date simply using `ts.date().isoformat()` without accounting for IST timezone or overnight shift rule R1. | An overnight shift punch-in at 02:00 IST was assigned the current day's date rather than the previous day's shift start date. | Implemented `determine_attendance_date` converting to IST and checking if punch time is before `shift_end` on overnight shifts. |
| 15 | `punch_in` (lines 104–105) | Check-then-insert pattern with `find_one()` before `insert_one()`. Vulnerable to race conditions. | Concurrent duplicate punch-ins both passed `find_one()` and resulted in duplicate records or unhandled errors. | Created a unique compound index on `(emp_code, date)` at startup and caught `DuplicateKeyError` to return HTTP 409. |
| 16 | `punch_in` (lines 119–120) | Injected `"id": str(res.inserted_id)` into response document. | Contract explicitly forbids `id` and internal `_id` on attendance records. | Removed `_id` and prevented adding `id` attribute to attendance records. |
| 17 | `PunchInIn` (lines 63–66) | Allowed arbitrary strings for `status` and unvalidated numbers for `punched_at`. | Client could pass `status: "INVALID"` or timestamps looking like seconds (< 100000000000). | Defined `PresenceStatusType` literal (`PRESENT`, `WFH`, `ON_DUTY`) and strict `EpochMillis` bounds. |
| 18 | `list_attendance` (lines 144–147) | Executed `list(db.attendance_logs.find(q))` loading all documents into application memory, sorted in Python, and manually sliced. | Catastrophically slow and high memory usage on 100,000 documents; causes memory exhaustion. | Delegated filtering, index-backed sorting (`.sort([("date", -1), ("emp_code", 1)])`), and pagination (`.skip().limit()`) directly to MongoDB. |
| 19 | `list_attendance` (line 145) | Sorted only by `date` descending, omitting secondary sort on `emp_code` ascending. | Attendance records on the same date appeared in indeterminate order. | Applied compound sort `[("date", -1), ("emp_code", 1)]`. |
| 20 | `list_attendance` (lines 125–132) | Accepted any dates without validating that `date_from <= date_to`. | Querying `date_from=2026-07-10&date_to=2026-07-05` returned empty results with 200 OK instead of HTTP 422. | Added validation checking `date_from > date_to` and raised HTTP 422. |
| 21 | `list_attendance` / `punch_in` (all output) | Datetimes (`punch_in`, `punch_out`, history timestamps) were returned as raw BSON/Python datetime objects. | Response JSON serialization failed or returned ISO string formats instead of required integer epoch milliseconds. | Created formatting helper that recursively normalizes BSON dates to integer epoch milliseconds. |
| 22 | Global / Startup | No indexes were created at startup. | Every query resulted in a collection scan (COLLSCAN) across the database; unique constraints were unenforced. | Added `init_indexes()` called during FastAPI lifespan to idempotently create unique and query indexes. |

### Items Examined and Decided Not to be Defects

1. **Storing plain strings for calendar dates (`YYYY-MM-DD`) and shift times (`HH:MM`):**
   Examined whether dates and shift times should be stored as BSON datetimes. Confirmed that DATA_MODEL.md section 1 explicitly mandates strings for calendar dates and shift times to avoid timezone distortion, so retaining strings is intentional and correct.

2. **Absence of internal `_id` in API responses:**
   Examined why `_id` is omitted in response models. Confirmed that both DATA_MODEL.md and `openapi.yaml` explicitly dictate that MongoDB's internal `_id` must never be exposed in any request or response, and attendance records have no business id.

3. **Returning HTTP 200 for empty search queries:**
   Examined if querying an existing employee or date filter with no matching records should return 404. Confirmed that list endpoints returning `{"items": [], "total": 0}` with status 200 OK adheres to standard REST practices and the API specification.
